# publish-kit 排障详表

> 原则：**先读该平台脚本文件头的坑位注释**（带实测日期），再跑探针，**不要靠反复实跑试探**。

---

## 环境层

| 现象 | 根因 | 处置 |
|---|---|---|
| `FATAL 找不到 config.yaml` | 没跑 init | `node bin/init.cjs`（**不要手工造 config.yaml**） |
| `连不上 CDP` | Chrome 没起 | `node bin/doctor.cjs`（不加 `--no-launch` 会自动拉起） |
| `端口被占用/拒绝访问` | 端口落在 Windows 保留段 | `netsh interface ipv4 show excludedportrange protocol=tcp` 查了，换 `runtime.cdp_url` |
| `patchright 未安装` | 依赖没装 | 在 publish-kit 目录下 `npm install` |
| 切平台后登录态丢失 | profile 被换 | `runtime.profile_dir` **定下就别移动**；换浏览器要重新扫码 |

## 登录层

| 现象 | 根因 | 处置 |
|---|---|---|
| `XX未登录` / `未登录或未加载完成` | 登录态失效 | `node bin/login.cjs <平台>` → **让用户自己扫码** → `node bin/doctor.cjs` 复核 |
| 登录页一直跳回 | 扫码没完成 | 别自动重试，让用户重扫 |
| 视频号壳首页在但表单不出现 | wujie 微前端没启动 | 脚本会点「发表视频」启动微应用；人工操作时先点它 |

## 填单层

| 现象 | 根因 | 处置 |
|---|---|---|
| `[交割护栏] 表单已填写，拒绝重复填单` | 页面上已有内容（疑似已交割给你） | **不要**直接加 `--force`。先看页面：是你之前填的吗？平台恢复草稿了吗？ |
| 选中的元素点不动 | 需要**真实 mouse.click**，合成 click 无效 | 读该平台坑位注释（微博 `a` 标签是典型） |
| 同一文案页面上有 5 个 | 命中了外层容器 | 按 `getBoundingClientRect()` 面积取最小 / 取叶子节点 |
| 图集只进去 1 张 | ① 批量多选不可靠 ② 上传区没初始化完就点 | 抖音改逐张传；微博等 composer 就绪 |
| 「已添加 N 张」与实际不符 | 那个文字统计的是**上传队列** | 数**实际渲染的缩略图**（限定在图集区/composer 内） |
| 话题变成乱码碎片 | 联想面板的**前缀替换** + 假候选 | 见下节 |
| 正文被顶替/截断 | 联想面板把词顶了 | 脚本有**回读校验**，不一致就抛错（宁可炸掉也不带脏稿交割） |
| 视频传不进去（>50MB） | Playwright 的 50MB 传输上限 | 走 `setVideoFile()`（CDP 原生直传），**不要自己写 `setInputFiles`** |
| 上传文件选择器不弹 | 入口偶发吞点击 | 脚本已统一重试 3 次（每次重新取坐标）；仍有则人工核对 |
| 封面上去了但预览没变 | 平台后台检测，文本不必然出现 | 看截图目检；脚本的 src 比对只告警不 FATAL |

## 抖音话题（最复杂的一块）

### 现象与根因

| 现象 | 根因 |
|---|---|
| 话题尾部变成 `#v#AA大人AI日报人人工智能大模型AAILLLM` | ① 联想面板**永远把你输入的词回显成一个「浏览量 0」的假候选** → 只按精确名匹配会把假候选当真，点下去不落 chip；② 用 `selectAllChildren`+`collapseToEnd` 挪光标会**破坏编辑器 selection 状态** → 面板不弹、文本插错位置；③ 面板**两段式渲染**（先回显、后远程列表，边打字边过滤）→「面板出现了」≠「列表到了」 |
| 所有词都判「话题库里没有」 | 只等面板出现就读候选，每次都只读到 count=0 的回显 → **要等连续两轮读到相同列表**（稳定）才判定 |
| 面板开了但点选没反应 | 按钮**零尺寸**（未 hover 时不占位）→ 用「尺寸为 0 就过滤」会把目标全滤掉；先 hover 曲名（鼠标**不要移开**），它才展开 |

### 正确的判据

1. 候选必须是 **精确名 且 浏览量 > 0**（浏览量文本要自己解析：`37.8亿` / `7901.7万` / `0`）
2. 定位用**同行**判定：`|按钮中心 y − 曲名中心 y| < 30px` 且文本含「使用」
3. 光标用 **`Control+End`**（`End` 只到当前折行行尾）
4. 点完 chip 是 `contenteditable=false` 的块，**不能逐字符回删**

> ⚠️ **同一段判定逻辑只保留一个实现。** 曾把「找曲名 + 找同行按钮」拆成两个函数，
> 逻辑看着一样，真机上一个能返回、另一个恒返回 null，排查绕了 8 轮。

## 抖音配乐

| 现象 | 根因 | 处置 |
|---|---|---|
| 点了「选择音乐」没反应 | 页面上这文案出现**两次**（行标题 + 动作按钮） | 点**动作按钮**（`class*="action"`），行标题点了不生效 |
| 找不到收藏里的曲子 | 面板是**右侧抽屉**不是 modal；「收藏」tab 在横向滚动区 | 用 `[class*="music-side-sheet"]` 判面板；tab 先 `scrollIntoView` |
| 找不到「使用」按钮 | 未 hover 时**零尺寸** | hover 曲名（不移开）让它展开；用同行判定找 |
| 点完配乐没生效 | 还要读扩展信息区确认 | 扩展信息区应变成「曲名 + 时长 + 修改音乐」；底部「确定」是**禁用态，不要点** |
| 配乐失败后合集点不到 | **抽屉没关**，挡住了下面的合集下拉 | 配乐流程 try/finally 无论如何都关抽屉 |

## 编排层（publish-all）

| 现象 | 根因 | 处置 |
|---|---|---|
| 缺物料参数 | `--media`/`--count`/`--body-file` 等必填项没给 | 脚本会**秒级报错且不启动任何平台脚本**（不会白开标签页） |
| 某个平台图集少图 | 并发触发**平台侧限流** | 并发上限设 5（默认）；9 全并发时知乎图集会卡在 7 张 |
| 墙钟比预期长 | 调度顺序 | 编排器**长任务优先**；若发现不是，看是不是某平台比预期慢（查 `logs/` 里的耗时表） |
| 想知道谁慢 | — | 每个平台的日志在 `publish.log_dir`（默认 `./logs`），收尾有**步骤耗时倒序表** |

## 清单层（publish-manifest）

| 现象 | 根因 | 处置 |
|---|---|---|
| `不认识平台 X` | 该平台不在注册表里 | 若走**零自动化** → 显式写 `via: manual`（只备料）；否则本工具确实不支持它 |
| `不认识开关 options.X` | 该平台没这个开关 | 查 `lib/manifest.cjs` 的 `OPTION_FLAGS`/`STEP_OPTIONS`/`VALUE_LESS_OPTIONS`。**不要**为了绕过它改平台脚本 |
| `平台 X 没有 image 形态的脚本` | B站与视频号只有视频线；公众号只有图文线 | 换形态，或拆成两个变体 |
| `图集不足` / `图集序号断了` | 目录里的图少于声称张数，或序号不连续（01,02,04） | 序号断了 = **顺序会错位**。确认是「漏生成」还是「命名跳号」，补齐再发 |
| `标题 N 字 > 上限 16`（视频号） | 视频号短标题是硬约束 | 用 `titleFile` 给一版**独立**的 ≤16 字短标题。**不要截取主标题**（截出来是半句话） |
| `视频号标题 20 字` 但没报 | 清单里没给 `titleFile`，标题回退到全局标题 | 补 `titleFile` |
| `B站缺 tags` | B站脚本不传标签直接报错 | 给 `tags` 或 `tagsFile`（B站不默认标签） |
| 槽位「0 步」 | 该槽位是 `via: manual` | 正常 —— 人工通道不执行任何自动化 |

## 失败诊断（`lib/diagnose.cjs`）

编排层失败时会自动分级。**照建议走，不要盲目重跑**：

| 级别 | 含义 | 允许自动重试？ | 处置 |
|---|---|---|---|
| `channel-dead` | 通道整体不可用（导航 / 执行上下文 / CDP） | ❌ | **别再填单**。`node bin/doctor.cjs`；平台可能改版 → 读坑位注释 |
| `login-required` | 登录态失效 / 公众号凭证与 IP 白名单 | ❌ | `node bin/login.cjs <平台>` 让用户扫码 |
| `content-rejected` | 素材或文案被平台拒 | ❌ | 改物料。**重试无意义** |
| `cosmetic` | **只是截图失败** | ✅ | 填单其实已经成了，通常不用管 |
| `retryable` | 偶发失败（超时 / 点击没生效） | ✅ | 编排层已自动重试一次；仍失败 → 按 `channel-dead` 处理 |
| `unknown` | 认不出来 | ❌ | 给人看，查 `publish.log_dir` 下该平台日志的最后几行 |

⚠️ **自动重试的边界**（别绕过它）：只重跑**失败的那一步**且该步必须幂等
（重新上传素材那一步不幂等 → 不重跑）；**API 通道（公众号永久素材）永不自动重跑**。

## 判据的通用陷阱

### 「判据的前提是 count 本身对」

任何「上传后确认成功」的判据都只能证明**页面上的东西**，证明不了**喂进去的东西**。

真实事故：投递单里某平台的图集列表只列了 1 张 → count=1 → 三个平台各只传了 1 张图，
而每个平台的判据都「通过」了（`渲染张数 ≥ count`，**1 ≥ 1 恒成立**）——
脚本报成功、语气笃定，结果三个平台全是残缺图集。

→ 脚本已加**起浏览器前的体检**：核对「声明要传几张」vs「目录里真有几张」，不过就不执行。

### 硬闸必须有实测依据

| 情况 | 该用 |
|---|---|
| 平台上限有实测回显（B站 2000/80、视频号 1000/16、公众号 1265/32） | **硬闸**（超了阻塞） |
| 只有公开口径、没有实测（微博/知乎正文 2000） | **软线**（超了只告警） |

猜一个上限会**误拦合法稿件** —— 宁可漏拦，不误拦。

## 调试纪律

自动化里出现「**逻辑看着对，但结果恒为空 / 恒失败**」时：

1. **写探针脚本在真机上 dump 地面真相** —— 逐值打印中间量，不要只打印最终结果
2. **探针里 import 真实模块、调真实函数**，与 DOM 快照**同刻对照**（读代码 ≠ 代码在跑）
3. **每轮改动只改一处**，否则无法归因

**别在同一个假设上调参数。** 抖音话题第一版假设「面板前缀替换」，照这个假设改了两次都失败；
真机探针一打，真因是「面板回显假候选」——与原假设无关。
